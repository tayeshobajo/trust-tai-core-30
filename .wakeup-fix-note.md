# Paperclip /wakeup — one-line client fix (NOT applied — acceptance run constraint)

Live acceptance run (2026-08-18) exposed it: `triggerHeartbeat` POSTs with no body,
but Paperclip 2026.722.0's `/wakeup` route requires a JSON object body.

- `POST /wakeup` no body   → 400 `{"error":"Validation error","details":[...path:[] Required]}`
- `POST /wakeup` body `{}` → 202 (queued heartbeat run)

My earlier curl tests passed because they always sent `{}`. The client never did.
The old 404-fallback chain masked this in reverse before (all paths 404'd, first
non-404 error surfaced). With `/wakeup` first, the 400 is now the failure mode.

## Fix (one line in src/lib/paperclip-client.server.ts)

```diff
       ],
-      { method: "POST" },
+      { method: "POST", body: JSON.stringify({}) },
     );
   },
```

`request()` already sets `Content-Type: application/json` when `init.body` exists
(paperclip-client.server.ts:141-143). No other call sites use requestFirstMatch.

## Verified live
- no-body: 400 (client's current behavior — broken)
- empty-object body: 202 + run JSON (fixed behavior)

Apply whenever ready; nothing else in the codebase depends on the no-body call.
